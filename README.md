# tachie-motion

**A local, cross-platform PSD character animation editor for synthetic speech (in development).**

PSD立ち絵と合成音声から透過MOVとOTIOを生成するローカルツールです。**Phase 0／Phase 1のCLIに加え、mainでは統合プリセット編集、Mac Finder選択、1 WAVのnone/open書き出し（上書き／別名）が利用できます。** 瞬き・aiueo・複数セリフ・タイムラインを備えた完成版ではありません。

### PSDプリセットの高速プレビュー（Issue #55 / PR #56、実装済み）

通常の初回PSD画像を表示した後、対応するPSDでは縮小レイヤー画像を
ブラウザへ読み込みます。準備完了後のレイヤーON/OFF・Open閉口/開口は
ブラウザ側で合成し、毎回のPython合成要求を省きます。未対応のPSDや
読み込み・復号・描画に失敗した場合は、元PSDの同一性を確認できたときだけ従来のPython合成に戻ります。

Canvas素材の準備中は旧レイヤー状態のPython送信を保留し、準備失敗時もPSDの同一性を再確認します。
高速プレビューで表示状態を変更する際は、まずPSDのファイル情報だけを照合し、
元PSDが外部で保存・差し替え・削除された場合は古いCanvas表示と編集を停止します。
明示的に再読み込みするまで旧レイヤー設定を新しいPSDへ適用しません。
この軽量確認はPSDの再解析やPython合成ではありませんが、ローカルAPI往復時間はかかります。

この高速経路は **プレビューだけ** です。元PSDの階層・名前・index-pathを変更せず、
MOV/OTIO/ProRes書き出しでは縮小画像を使用しません。RGB/8bitの通常ブレンド、
不透明度100%など、保守的に安全と判定できるPSDだけを対象にします。
マスク・クリッピング・特殊描画モード・効果・調整レイヤーなどは
現在Python合成で表示します。高速プレビューのピクセル単位の完全一致は
保証せず、縮小時の輪郭や色に若干の違いが出ることがあります。
PR #56のPython・Web UI CIと独立コード監査はPASS。2026年11月3日にMac実PSDでレイヤー切替の体感速度改善をHuman確認しました。画質の厳密な比較と定量的なブラウザ描画時間計測は未実施です。

### WAVの音量から口状態JSONを生成する（Phase 1 Slice 1）

```sh
tachie-wav-mouth \\
  --wav "speech.wav" \\
  --fps 30 \\
  --open-threshold 0.05 \\
  --close-threshold 0.025 \\
  --output output/mouth-frames.json
```

非圧縮整数PCM WAV（8/16/24/32-bit、mono・複数チャンネル）を解析し、各フレームのサンプル開始・終了位置、正規化RMS、口状態（`closed` / `open`）を出力します。WAVは変更しません。映像フレーム数は音声サンプル長から切り上げ、末尾は端数フレームになり得ます。

`--open-threshold` と `--close-threshold` は開閉のチャタリングを減らすための暫定閾値です。音声によって調整できます（`0 < close <= open <= 1`）。既存のJSON出力は上書きしません。**このCLIは口レイヤー・PSD・MOV・OTIOをまだ生成しません。**

### 手動口レイヤー指定で透過MOVと同期OTIOを生成する（Phase 1 Slice 2）

`tachie-psd-inspect`で口閉・口開のレイヤーインデックスパスを確認してから指定してください。次の`4/0`と`4/1`は例であり、実際のPSDに合わせて変更します。

```sh
tachie-psd-inspect "character.psd"
tachie-mouth-render --psd "character.psd" --wav "speech.wav" --mouth-closed "4/0" --mouth-open "4/1" --fps 30 --output-mov "output/speech.mov" --output-otio "output/speech.otio"
```

PSDの表示状態を基本として、指定した2つの口レイヤーだけを入れ替えます。非表示の親グループにある口レイヤーの強制表示や自動レイヤー検出はしません。元PSDとWAVは変更せず、既存のMOV・OTIOは上書きしません。

WAVのサンプル長を時間基準にし、映像の最終フレームだけ1フレーム未満を切り上げます。個別OTIOでは動画と音声がともに0から開始し、音声は元の長さのまま1回だけ参照します。**通常の書き出しではWAVを複製しません。** 個別OTIOは、MOVを従来どおり`file://` URIで参照し、元WAVはUnicodeを含む元の絶対ファイルパス（`file://`なし）で参照します。日本語・結合文字を含むWAVの`file://`参照でDaVinci Resolveがオフライン表示したMac実例に対する限定的な互換性対策です。元WAVの保存先を変更したり外付けSSDを外したりすると参照切れになります。持ち運び用のWAV同梱は将来の**明示的な選択機能**とし、現在は未実装です。2026年10月30日にMac実WAV（日本語・結合文字入り）を使い、修正版OTIOのResolve取り込み・映像と音声の自動オンライン・再生同期を人間がPASS確認しました。Windows等の互換性は未検証です。可変フレームの口パクでは`--reuse-packets`最適化は利用しません。この実機PASSは当該PSD・WAV・Mac環境の結果で、すべての素材・環境を保証するものではありません。

### プリセットUI（PR #28・#32）

PR #28（旧Private開発履歴）でPSDプリセット一覧・詳細編集を実装し、Issue #31（旧Private開発履歴） / PR #32（旧Private開発履歴）でAndroid実機フィードバックによる操作改善を追加しました。いずれもmain統合済みです。

- 画面上部の「プリセット」でPSD絶対パスを指定して「読み込む」を押すと、「通常」プリセットを作成します。一覧は「＋ 作成」、カードの「詳細を編集」から編集します。元PSDのレイヤー名・階層・可視状態は保持し、ON/OFF静止画プレビューを更新します。
- **作成・編集・並べ替え・複製・名前変更・名前の編集中の文字列**は、同じブラウザと同じHTTPSオリジンのローカルストレージへその場で自動保存し、再読み込み時に元PSDを再解析してfingerprintとレイヤーindex-pathが一致するときだけ自動復元します。元PSDが移動・変更された場合や保存データが不正な場合は、既存の復元データを保持したまま復元を中止します。「保存済みを破棄して新規」で明示的に破棄できます。

- 同名プリセットは作成しません。新規・複製は番号や「コピー」を付けて自動命名し、改名による重複は拒否します。内部IDは名前・順序と独立です。

#### Androidへ一括接続する（Issue #29、任意）

この起動補助機能はPR #30でmainへ統合済みです。MacのローカルWebサーバーとtachie-motion用**8443番のTailscale Serve**を同じコマンドで管理します。既存のVoiceger Editor用443番の設定には触れず、Funnelや常駐・自動起動は行いません。これはD20の「使うときだけ起動」の運用です。

**最初の1回だけ**、リポジトリの`.venv`にPython依存と`frontend/node_modules`が用意されている必要があります。下記を1つのMac/Termiusセッションから実行します（作業ツリーがdirtyでもGitを変更しません）。

```sh
cd "$HOME/Code/tachie-motion"
.venv/bin/python scripts/run_android_web.py
```

このコマンドは、実行中のcheckout HEAD確認→現在のフロントエンドをViteで再ビルド→8765番のローカルヘルスチェック→8443番のServe起動（既に**正確な同一ルートがある場合は再利用**）→tailnet HTTPSで`/api/health`へ接続、という順番です。**両方のヘルスチェックに成功した場合にだけ**`ANDROID_READY: https://...:8443/`を表示します。Android上での実際のブラウザ操作がPASSしたという意味ではありません。

前提条件の不足・8765番のポート競合・8443番の他アプリ宛て転送・Funnel設定がある場合は`BLOCKED:`で停止します。ほかのプロセスをkillせず、既存の443番や8443番の設定をリセットしません。Macの`tailscale status --json`から正規のtailnetホストを取得するため、Originを手入力する必要はありません。

停止する場合は**その同じTermiusセッションでCtrl+C**を押します。このコマンドが起動したローカルWebと8443番Serveのみを停止し、以前から存在するServeはそのまま残します。Termiusを終了すると接続も停止します。動かし続けるための常駐サービスや`--bg`は標準では使用しません。

以前の2セッション手動起動手順は、起動スクリプトが使えない環境のための**代替手順**として下に記録しています。


### Mac ChromeでFinderからファイルを選ぶ（Issue #20 / PR #39）

**Mac本体で、既存サーバーをCtrl+Cで終了してから起動します。** Finderを使う通常操作では絶対パスを入力しません。

```bash
cd "$HOME/Code/tachie-motion"
.venv/bin/python scripts/run_mac_web.py
```

- Macブラウザで表示された `MAC_READY: http://127.0.0.1:8765/` を開きます。PSDは「Finderで選ぶ」、セリフWAVは「Finderで選ぶ」、出力先は「フォルダを選ぶ」。選択成功後に既存のPSD/WAV解析へ渡します。**PSD・WAV・出力先はそれぞれ最後に選んだフォルダをブラウザ内に個別保存**するため、次回はその場所からFinderを開きます。初回のみそれぞれの場所へ移動が必要です。キャンセルは現在の選択と記憶済みフォルダを変更しません。保存した場所が見つからない場合は通常のFinder選択に戻します。
- Mac専用ランチャーは現在のfrontendをビルドし、Web APIを `127.0.0.1:8765`、Finderダイアログ専用APIを **`127.0.0.1:8766`** で起動します。いずれもフォアグラウンドで、Ctrl+Cで起動した子プロセスだけを停止します。ポート競合は停止し、他サービスをkillしません。Tailscale ServeやVoiceger 443番は操作しません。
- FinderダイアログAPIは独立プロセス/ポートで、Mac上の`http://127.0.0.1:8765`のブラウザからのみ呼び出せます。Tailscale経由のAndroidからは呼び出せません。通常の `tachie-web` やAndroid起動時は「パスを直接入力（補助）」を使えます。
- 元PSD/WAV/LABは選択・書き出し時にも変更せず、Webブラウザへのファイルアップロードをしません。手動の直接パスは折りたたみ欄に残します。
- Finderからブラウザへのドラッグ＆ドロップは**未実装**です。標準ブラウザではFinderの元パスを取得できず、アップロードへの置換も行いません。Windows Explorer選択は別ゲートで未検証です。
- Finder表示にはMacのログイン済みデスクトップセッションが必要です。Termius/ヘッドレスでダイアログ表示を保証しません。

### キャラクター設定JSONの保存・読み込み（Issue #44 / PR #45）

「プリセット」画面の「キャラクター設定」欄で、**JSONを保存**すると、デスクトップ版Chrome/Edgeではブラウザ標準の保存ダイアログが開き、`tachie-character.json`を初期名として**保存場所と名前を選べます**。保存完了・キャンセル・失敗は画面に表示し、保存中の連打は無効にします。標準保存ダイアログ非対応のブラウザではエラーを表示し、無断の自動ダウンロードは行いません。「JSONを読み込む」からファイルを選ぶと、保存した設定を再読み込みできます。プリセットの安定ID、名前・表示順、既定ID、基本のレイヤーON/OFF、登録したOpen口形（他の任意設定がある場合はそのデータも）を保持します。名前変更欄の入力途中の文字やプレビュー画像、PSD/WAVそのものはJSONに含めません。

読込み時はJSON内の**元PSD絶対パス**からPSDを再解析し、保存時のファイルサイズ・更新時刻fingerprintおよび全レイヤーindex-pathを照合します。PSDが移動・変更された、ファイルが壊れている、形式が未対応の場合は読込みを中止し、現在の編集内容とブラウザの復元データを保護します。この初期版では**元PSDのパスが同じであることが必要**で、パスの自動置換や異なるPSDへの関連付けは行いません。fingerprintは軽量な変更検出であり、暗号学的な同一性保証ではありません。

既存の編集を置き換える場合は確認ダイアログが出ます。読み込み成功後はブラウザ自動復元も更新されます。JSONはブラウザの標準保存ダイアログ／ファイル選択で扱います。選択した既存JSONへの保存はブラウザの確認に従い、サーバーが任意のJSONファイルを上書きすることはありません。**制作プロジェクトの保存、WAVやタイムラインの保存とは別機能**です。「JSONを保存」「JSONを読み込む」は並んだボタンで、読み込み結果は同じ欄に表示します。GitHub Actionsの合成素材テストとMac実PSDの見た目・操作感の確認は別ゲートです。

### Web UI（プリセット→セリフ）

1. 「プリセット」でMac上のPSDを読み込み、統合プリセットを編集します。大きなPCウィンドウでは横長カード、狭い画面では補助レイアウトです。
2. プリセットの詳細で「口パク（open）」の対象レイヤーを手動で選択し、閉口と開口でのON/OFFを登録します。対象は複数レイヤーにできます。元PSD名・順序・階層は変更しません。
3. 「セリフ」画面でWAV絶対パスを確認、プリセットと口パク方式（なし／open）を選び、既存のMac出力フォルダとファイル名を指定します。選択したプリセットの表示状態をもとに透過MOVと個別OTIOを生成します。
4. aiueo・瞬き・複数キャラ/WAV・変更点・待機はまだ選べません。口形未設定・元PSD変更・隠れた親を持つ口形指定は書き出しを拒否します。WAVは元ファイルをOTIOから参照します。既存MOV・OTIOが両方ある場合は、上書き（既定）／別名で書き出すを選べます。

このWeb UIでの実PSD・WAVによる書き出しとDaVinci Resolveの映像透過・口パク・音声同期は2026年11月1日にMacでHuman PASS確認済みです。旧Phase 1 UIのWeb `/api/export` は後方互換テスト用に残していますが、画面からは使用しません。

ブラウザで`http://127.0.0.1:8765/`を開き、使用後は起動したターミナルで**`Ctrl+C`を押して停止**します。ブラウザを閉じただけでは停止しません。常駐・Macログイン時の自動起動・`launchd`登録・`nohup`等によるバックグラウンド起動は標準運用ではありません。この方針の正本は[Decision D20](docs/DECISIONS.md)です。

ローカルサーバーは常に`127.0.0.1`だけで待ち受けます。別端末からはSSHローカルポート転送、または**明示的に有効化したTailscale Serve（tailnet内限定）**で接続できます。サーバーをLANに直接バインドしたり、Tailscale Funnelでインターネットへ公開したりしません。PSD・WAV・出力フォルダの絶対パスと、出力ファイル名（英数字・アンダースコア・ハイフンのみ）を入力します。出力フォルダは事前に作成してください。WAVは複製せず、元WAVを絶対パスで参照します。新しい「セリフ」画面では既存MOV／OTIOの完全な組を明示的に上書きできます。旧試験版 `/api/export` とCLIは既存ファイルの上書きを拒否します。

#### Android / TermiusからTailscale Serveでアクセスする（任意）

既存の443番で別アプリ（例：Voiceger Editor）が動作している場合、**その設定は変更しません**。tachie-motion専用にHTTPS **8443番**を使います。サーバー自身は127.0.0.1:8765のままで、Tailscale Serveがtailnet内のHTTPS要求だけを転送します。MacのSSHターミナルを2セッション使用し、両方とも**使うときだけ**起動します。

Termius セッションA（Webサーバー）：次のURLは自分のTailscaleマシンのFQDNに置き換えてください。末尾`/`は付けません。

```sh
cd "$HOME/Code/tachie-motion"
source .venv/bin/activate
TACHIE_TAILSCALE_ORIGIN="https://my-mac.my-tailnet.ts.net:8443" tachie-web
```

Termius セッションB（Tailscale Serve）：**8443番が未使用であることを`tailscale serve status`で確認した後**に起動します。

```sh
cd "$HOME/Code/tachie-motion"
tailscale serve --https=8443 8765
```

スマホ（同じtailnetに参加済み）のChromeで`https://my-mac.my-tailnet.ts.net:8443/`を開きます（実際のFQDNに置換）。**終了時はセッションBのServeとセッションAのWebサーバーをそれぞれ`Ctrl+C`で停止**します。Serveを`--bg`で常駐させる必要はありません。既存443番のServe設定は操作しません。

`TACHIE_TAILSCALE_ORIGIN`は指定した`https://...ts.net:8443`のHostとブラウザOriginだけを追加許可するオプションです。**未指定時は従来どおりlocalhost限定**で、任意の外部Originは拒否します。これは公開インターネット向けの認証機構ではありません。tailnetの参加者・共有設定には注意してください。接続やPOSTが失敗した場合、Host/Originの制限を解除せず、FQDN・8443番・Serveの状態を確認してください。

Web UIは初期実装です。口形の登録はプリセット詳細で行い、セリフ画面は保存されたプリセットを元PSDと照合してから使用します。PSDプレビュー・書き出しのキャンバス安全上限は6,000万画素です（既存CLIとは別）。Linux CIの合成素材とMac実素材のGUI/Resolve Human E2Eは別判定です。

### PSDを調べ、手動で状態PNGを生成する

```sh
tachie-psd-inspect "character.psd"
tachie-psd-bounds "character.psd"
tachie-psd-render "character.psd" --output-dir output/psd-preview
tachie-psd-variant "character.psd" --fixed-crop --output output/state-closed.png
tachie-psd-variant "character.psd" --show "4/0" --hide "4/2" --fixed-crop --output output/state-open.png
tachie-psd-fidelity "character.psd"
```

`--show` / `--hide` の `4/0` 等は説明用の例です。対象PSDの実際のレイヤーパスを `tachie-psd-inspect` で確認してください。2種類の状態PNGは同じサイズで、アルファチャンネルが必要です。

### 透過MOVと個別OTIOを生成する

```sh
tachie-prores-poc \
  --frame output/state-closed.png \
  --frame output/state-open.png \
  --fps 30 --frames-per-state 15 \
  --reuse-packets \
  --output output/mouth.mov

tachie-otio-poc \
  --mov output/mouth.mov \
  --test-tone \
  --output output/mouth.otio
```

`--test-tone`は検証用WAVを生成します。実際の音声を使う場合は `--test-tone` の代わりに `--wav path/to/voice.wav` を指定し、MOVとWAVの尺を一致させてください。現在のCLIはWAVを解析してPNG状態を自動切替するものではありません。

`--reuse-packets`は省略可能です。FFmpegの対応条件を満たさない場合は従来方式へフォールバックします。出力先の既存ファイルは上書きせず、検証に失敗したMOVは公開しません。ファイルシステムが安全なハードリンク公開に非対応の場合もエラーになります。

### PSDレイヤー一覧の表示・Open口形・位置選択（Issue #40 / PR #41、Issue #53 / PR #57・#58）

プリセット詳細の元PSDレイヤーツリーではレイヤー名のクリックが選択（プレビューに外接矩形を表示）、左のチェックボックスが基本ON/OFF、右端がOpenの役割をワンクリックで指定する「なし／閉／開」ボタンです。1プリセットに閉口・開口の各1完成形を設定し、複数のPSDレイヤーで1口形を構成できます。「なし」のレイヤーは基本表示を維持します。

選択中の行は強調表示され、「選択位置へ」でプレビューを拡大できます（外接矩形が有効なレイヤーのみ）。名前の選択だけでは表示状態・Open割当・保存データを変更しません。検索やグループ折りたたみで選択行が隠れても、選択位置は保持されます。範囲が不明なレイヤーは名前だけを表示します。階層開閉、レイヤー検索、割当済みのみ表示が利用できます。右のプレビューは基本表示／閉口／開口を切り替えて確認します。旧UIで作成した特殊な口形割当は破棄せず「既存の個別設定」と表示し、変更するレイヤーだけ明示的に再割当します。

aiueo・目パチのタブは拡張先を示す**未対応表示**であり、現時点では設定・書き出しできません。Openのしきい値・反応速度など、音声に対する動作パラメータはレイヤーの役割とは別に将来のWAV×キャラクター編集画面で扱います。


#### プレビューの反復表示キャッシュ（Issue #47 / PR #48）

同じPSD・同じレイヤー表示状態を再び表示する際は、完成済みPNGを最大6状態までメモリ内で再利用します。元PSDの変更や表示状態の違いは区別し、元ファイルは変更しません。

Mac実PSD（1500×3300px、85レイヤー）でのサーバー内関数の計測では、通常表示の初回が2.288秒、レイヤー変更後の初回が2.481秒、両状態への再表示はいずれも0.000秒（小数第3位への丸め）でした。キャッシュヒット2回・ミス2回、PSD原本不変を確認しています。**これはPR #48時点のサーバー内関数の計測であり、ブラウザ上の体感・描画時間ではありません。** PR #50の安全条件を満たす単一レイヤー変更は後述のROI部分合成へ進みます。初回やROI非適用時の全面合成（約2秒）は未解決です。

#### PSDの新規レイヤー状態の部分合成（Issue #47 / PR #50）

初回PSD読込で生成したRGBA全解像度画像を**最大1状態・32MiB**までメモリに保持し、同一PSDスナップショットで単一の通常ピクセルレイヤーだけが変更された場合、影響矩形（面積40%未満）のみ合成する高速経路を試します。既存の完成PNG 6状態キャッシュは維持します。Mac M1実PSDのサーバー内関数では初回2.688秒、新規レイヤー状態0.361秒（全面合成単体の参照値は1.913秒）でした。ROIは実際に実行され、RGBA画素・PNG復号後画素は完全一致、ICCプロファイルは作成日時以外一致し、元PSDは不変でした。

**RGB 8bitかつ通常合成の単純なPSDのみ**を対象とし、マスク、エフェクト、クリッピング、特殊なブレンド・不透明度、グループON/OFF、複数レイヤー同時変更、対象矩形が大きい場合、部分合成エラー時は従来の全面合成へフォールバックします。PSD原本や動画出力処理は変更しません。初回の全面合成は短縮されず、Mac実PSDのAPI/ブラウザでの速度・メモリ・表示画質は別途検証する必要があります。

#### 実PSDプレビューの全体表示・拡大（Issue #40 / PR #41）

プリセット詳細の右側プレビューは、縦長PSDでも常に画像全体を表示するよう固定高さの領域内に収めます。「＋」「−」で最大8倍まで拡大・縮小し、拡大時はドラッグ（キーボードでは矢印キー）で移動できます。Openレイヤーを割り当てた後は「口元へ」で対象レイヤーの外接矩形付近を中心に拡大できます。「全体表示」で初期位置・倍率に戻ります。基本表示／閉じ口／開き口を切り替えても倍率・位置は保持します。ブラウザの表示操作のみで、元PSD・保存済み設定・MOVの出力範囲には影響しません。2026年11月1日にMac実PSDで全体表示・口元フォーカス・表示切替の操作性をHuman PASS確認しました。


### 新しいセリフ書き出しでの同名MOV/OTIO（Issue #42 / PR #43）

- **既存の2ファイルが両方ある場合**、上書き（既定）または別名で書き出すを選択可能。別名の場合、使用していない `_002` などの候補を提示し、編集できる。生成結果には実際の保存先を表示する。
- どちらも存在しなければ通常の新規書き出し。**片方だけ存在、またはシンボリックリンク／通常ファイル以外**がある場合は、その名前への上書きを許可せず、別名の新規出力へ切替。
- 上書きでは新しいMOV・OTIOを事前に生成・検証してから、既存2ファイルのハードリンクバックアップを `.<basename>.tachie-backup/` に保持し、同じパスで更新する。**通常の更新失敗は元の出力を復旧**し、元PSD/WAVは変更しない。
- 注意：異なる2パスの同時原子的更新はできない。強制終了・電源断の間に片方だけ新しくなる可能性がある。その場合、バックアップディレクトリを残して元ファイルを復旧可能にし、同名への次の書き出しは停止する。バックアップを確認する前に手動削除しないこと。通常の公開では元の出力をバックアップ領域へ移動し、完成済みの新規ファイルを排他的に配置する。競合する外部更新を検知した場合は該当ファイルを削除せず復旧領域に保存し、手動の確認が済むまで同名書き出しを拒否する。MOV・OTIOの公開が完了した後にバックアップや一時レンダリング領域の削除だけが失敗した場合は書き出し成功とし、画面で残存パスを警告する。新規書き出しでも復旧領域 `.<basename>.failed-*` を最初の公開前に確保し、競合ファイルが残った場合は復旧確認まで同名書き出しを拒否する。外部アプリによる同一inodeへの書き込みや電源断の完全なトランザクション保証は提供しない。
- 既存の旧試験版書き出しAPI／CLIの「上書き拒否」は変更しません。新しい「セリフ」書き出しの上書き／別名はPR #43で実装し、2026年11月1日にMac実素材＋ResolveでHuman PASS確認済みです。GitHub ActionsによるPR #43最終HEADのCI実行は利用枠不足で未実施です。
