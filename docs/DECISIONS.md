# Decision log — updated 2026-11-21

These decisions are carried from product planning. Changes require an explicit product decision and docs update.

| ID | Decision |
| --- | --- |
| D01 | Independent editor, not a DaVinci Resolve-specific plugin. |
| D02 | Cross-platform local Web app: macOS and Windows first, Linux-friendly. |
| D03 | React/TypeScript/Vite frontend and Python/FastAPI backend are the initial technical direction. |
| D04 | FFmpeg is installed by the user; do not bundle it initially. |
| D05 | Initial character source is exactly one PSD; preserve its original layer hierarchy/order/names. |
| D06 | No automatic eye/mouth detection. Human manually assigns animation layers. |
| D07 | Expression and pose are combined into **one named preset**. A preset stores per-layer ON/OFF, can be created/duplicated/renamed/deleted/reordered, and only bound lip/blink targets override its base visibility. |
| D08 | One WAV is the primary animation unit, but it may drive several character MOVs (including non-speaking reactions). |
| D09 | Each **WAV × character item** chooses lip mode: none/Open/aiueo. One preset can store the movable Open-open shape and independent aiueo (a/i/u/e/o/ん) definitions. Resting Open-close always uses the preset fixed-layer state; fixed and selected movable leaves may coincide, while unselected movable leaves remain hidden. Earlier JSON formats are not migrated (revised 2026-11-18, Issue #32). None still uses WAV timing/preview. |
| D10 | Blink intervals configurable per character, non-synchronized via phase/random variation; each unified preset can disable eye motion or set multi-layer close eyes. Resting eye-open uses fixed layers; the close-eye shape must be explicitly selected, even when it matches the fixed pose; unselected editable eye leaves are hidden. **Approved 2026-11-18 (Issue #34):** character-wide initial blink timing is interval 3000ms, closed 120ms, jitter ±500ms, first blink phase 700ms and seed 0, saved durably on character initialization rather than displayed as unsaved suggestions. Missing timing in an existing current-format character/draft/project is initialized and persisted on successful load; explicitly customized timing is never replaced. Eye motion still starts OFF per preset until the user enables it and selects the close-eye pose. **Revised 2026-11-19 (Issue #36):** per-export reproducibility is NOT required; each utterance MOV generates fresh randomness to vary both the first blink around the configured phase (± jitter) and subsequent intervals (interval ± jitter). Re-exporting the same WAV may produce a different blink pattern. Remove the user-facing reproducibility seed control; the legacy seed field is retained only to load current stored JSON but is ignored during rendering. Zero jitter preserves intentionally fixed timing. |
| D11 | Timeline editing uses change points (not draggable duration clips). |
| D12 | Every WAV/idle item has an independent initial unified preset per character; no implicit inheritance. Per-time preset change points belong to WAV utterances only. Idle MOVs use one fixed preset and optional blinking (2026-11-21 user decision). |
| D13 | Reusable loopable idle MOV library plus special per-scene idle of arbitrary duration. |
| D14 | Export character-sized fixed transparent canvas, consistent across poses/items/rerenders. |
| D15 | Initial media output is ProRes 4444 alpha MOV; 30fps default, configurable 24/60. |
| D16 | **Revised 2026-11-19, Issue #38 (user approved): Individual utterance export outputs one PCM-in-MOV only, without individual OTIO. Batch export outputs all MOVs plus exactly one combined OTIO** (no per-utterance OTIO). Historical rule in Issue #18 (2026-11-11) generated an individual OTIO, now superseded. The combined OTIO references each designated PCM-containing MOV exactly once on its audio track and uses separate video tracks per character when implemented. Existing OTIOs must never be deleted. Because an OTIO of any basename in the output folder might reference an existing MOV, solo MOV overwrite is conservatively refused when such an OTIO exists; choose a new basename. Batch-wide interrupted-recovery state blocks all solo destinations until reviewed. Multiple character MOVs from one WAV must not embed duplicate PCM; idle MOVs have no audio. |
| D17 | **Do not copy or bundle source WAVs in any export**, including portable output. Embed the input WAV-derived lossless integer PCM in the designated utterance MOV, preserving the source WAV unchanged. OTIOs reuse generated MOV media without duplication. The legacy standalone `tachie-otio-poc` remains a separate compatibility PoC, not the production media-output contract. |
| D18 | Separate reusable character profile from project file; snapshot used settings; rerender changed MOV only. |
| D19 | Private during early development, public OSS release is the long-term aim; license not yet selected. |
| D20 | Local Web UI runs **on demand, in the foreground** with `tachie-web` and stops with `Ctrl+C`; no auto-start, persistent web daemon/launchd or `nohup` by default. The backend remains bound to `127.0.0.1`. Remote Android access may use **Tailscale Serve (tailnet-only HTTPS)** on a separate port 8443 to loopback 8765, without altering an existing Voiceger Serve on 443; the browser-facing origin is explicitly allowlisted with `TACHIE_TAILSCALE_ORIGIN` and checked by Host/Origin validation. Serve is started/stopped on demand for the session; never use Funnel or bind the backend to a LAN/Tailscale address. SSH local port forwarding remains a supported alternative. |
| D21 | Character setup top page lists presets with previews; each preset has a dedicated detail page. Presets support duplication, free renaming, deletion and drag-and-drop reordering; stable internal IDs preserve references. |
| D22 | Each PSD layer in the base preset has only ON/OFF. Mouth and eye states can comprise several layers together. The dynamic renderer may override **only** the respective target layers. |
| D26 | 2026-11-17: Use **original PSD layer groups** as the unit of animation targeting; multiple groups may feed one action's independent leaf-level shapes. Keep **fixed** and **movable** PSD trees separate in the editor. Group bindings are character-wide, while mouth/blink motion can be disabled per unified preset without deleting shape settings. A hidden parent always hides its children. One PSD group cannot be assigned to competing animations in the initial UI. Preserve optional PSDTool name prefixes as controls: `*` is an exclusive radio within the same immediate PSD parent; `!` is mandatory visible. Plain names stay ordinary checkboxes. |
| D25 | Batch overwrite is a whole-generation operation: stage/validate all PCM ProRes MOVs and one combined OTIO first, retain a durable manifest plus hardlinked originals until all names are published, and restore all originals on ordinary failure. Interrupted publication leaves a manually recoverable backup and blocks future writes until inspected. Users can instead choose one common suffix for the entire new generation (Issue #18, approved 2026-11-14). |
| D24 | The only naming placeholders are `{番号}` (WAV-list order, padded to 3 digits), `{WAV名}` (source WAV stem), `{キャラ名}`, `{プロジェクト名}`. **Single and batch MOVs share the default `{番号}_{キャラ名}_{WAV名}`**; batch OTIO default `{プロジェクト名}`. Reaffirmed 2026-11-19 for future multi-character rendering: the WAV-list number is shared by every character in one utterance, while the character token distinguishes their MOVs. Preserve source WAV numbering even when it results in duplicate-looking prefixes. Keep auto-generated solo names in sync with list reordering and template edits; an explicitly edited solo basename remains fixed. Japanese, spaces and decomposed Unicode must be preserved safely. File extensions are automatic and actual resolved filenames must be shown before exporting (Issue #18, approved 2026-11-11). |
| D23 | aiueo has six defined mouth shapes: a/i/u/e/o/ん, with ん used as silent/rest mouth. WAV selection probes an exact sibling .lab path preserving original filename characters; a missing/invalid LAB disables aiueo, without inferred phonemes or automatic mode fallback. All six mouth shapes require an explicit positive layer selection. An empty shape is unconfigured, shows no editable mouth leaves in the preview and prevents aiueo export. No inheritance checkbox or legacy-format migration. **2026-11-19 / Issue #40 user-approved exception:** If *only the final* LAB interval is `pau` and starts before the PCM WAV endpoint, clamp its end to the floor of the exact rational sample duration in 100ns ticks in memory; leave WAV/LAB unchanged. Reject earlier overruns, all non-`pau` overruns, pauses starting at or beyond WAV end, overlaps and unsupported phones. Keep the LAB status, render and pre-publication revalidation consistent. |
| D27 | **2026-11-17 user-approved aiueo MOV rule:** sample the center of each video frame in WAV sample-time using exact integers, clamping the last partial frame to an actual PCM sample; map consonants to the **next LAB vowel** (including vowels shorter than one video frame) until a silence, gap or moraic nasal N; use ん if no next vowel. Uppercase devoiced A/I/U/E/O use their lowercase vowel shape. LAB pause/silence/N/gaps use ん, with no inferred phonemes or Open fallback. |

| D28 | **2026-11-19 approved, Issue #44:** A large blocking modal overlays the editing screen during solo or batch exports; show real stage/frame-based percentage, active WAV, item count and error state. Allow the user to cancel while media generation is running, but only report “cancelled” after the server stops. Never cancel partway through the generation-wide public batch commit. Preserve originals, existing MOV/OTIO, recovery evidence and the existing transactional safety contract. Closing or refreshing the tab is not a cancel action. |
| D29 | **2026-11-21 approved, Issue #49 / Draft PR #50:** Adopt project JSON **v4** with required per-WAV `presetChanges` (PCM integer sample position + stable preset ID), and explicitly reject v1–v3 on import rather than silently migrate. Change points have no separate persistent ID; the sample position is their key. Preserve source-identity validation and original media. The current renderer retains a conservative **64 distinct configurations / 512 MiB RGBA pose image** safety limit; an over-budget export fails without publication. The cap may be reconsidered using actual PSD measurements, not silently bypassed. |
| D30 | **2026-11-21 approved:** A silent idle MOV needs a single fixed preset with optional eye blinking, not timed expression/pose changes. When character A speaks and character B reacts, B's expression changes belong to the *WAV utterance's listener-character* timeline, not the idle MOV. Multi-character listener reactions remain a future feature. |

| D31 | **2026-11-22利用者承認、Issue #62 / A案**：内容・描画レシピと生成履歴の整合が確認できる未変更の公開MOVは、最初に公開されたファイル名・パスを変えずに再利用する。一覧並べ替えのみの場合は全体OTIOだけをWAVの新しい順序に更新し、MOVの再エンコード・改名・再公開は行わない。結果として既存MOVの名前の連番と現在の順序は一致しなくてもよい。初回生成・新規生成・再生成はD24の安全な命名／衝突規則に従い、既存の単一MOV名変更と手動名の契約は維持する。UIは自動名と再利用する実パスを区別する。 |

| D32 | **2026-11-23利用者承認（新制作ワークフロー #66〜#74）**：セリフ後・末尾の待機は固定プリセットの透過静止画とし、旧D12/D13/D30の「待機MOV」方式をこの制作フローでは置き換える。待機秒数・FPSは制作プロジェクト共通。待機区間ごとにキャラ別プリセットを切替可能。聞き手の他キャラ発話中は静止画ではなく、口パクOFFでもアニメーションMOVとする。汎用ループ機能は対象外。待機PNGのOTIO表現・Resolve互換性はIssue #66の合成PNG PoCで部分Human PASS（24/30/60fps、指定尺、複数回参照、延長）。別名パスと実PSD由来の品質は継続検証。 |

| D33 | **2026-11-23利用者承認、Issue #66**：全体共通の待機秒数は、FPSを掛けた値を**四捨五入（0.5フレーム以上切り上げ）**して整数フレームに変換し、正の秒数は最低1フレームとする。計算はFraction等の有理数・整数演算で行い、浮動小数点の誤差で境界を変えない。変更ごとの別FPSや秒数を保存しない。24/30/60fpsのfloor/ceil双方のResolve表示はHuman PASS。製品への正式統合は別Issue。 |

## Unresolved decisions / validation

- Public OSS license, attribution, trademark/project identity.
- Exact package/distribution method for Python backend; FFmpeg external.
- Parent visibility follows the source PSD (D26). Precedence and conflict handling when mouth/eye targets overlap remain unresolved; do not infer a priority.
- **Issue #49（2026-11-20承認）**：現在編集中のWAV初期プリセット・変更点で参照中のプリセットは削除拒否（`PRODUCT_SPEC.md` §4）。登録中のWAVも保護し、API応答後に参照が無効なら登録を中止。未読の別ファイルに保存された制作プロジェクトの参照まで調査する仕様、および以前の単一レイヤーバインドの移行方針は未決。
- Absolute vs relative media-link behavior per OTIO importer; verification required.
- **2026-11-06 decision, Issue #2:** WAV-derived non-compressed PCM in utterance MOV is the agreed output contract; do **not** offer WAV copying, even as an optional portable-output feature. Mac DaVinci Resolve standalone MOV and individual OTIO Human E2E PASS; independent code review and synthetic CI PASS were recorded separately. Combined OTIO / multi-character behavior remains planned, including selection of the single audio-owner MOV when multiple characters or no speaker image is rendered; do not describe the future workflow as implemented.
- PSD compositing fidelity boundaries and fallback/error presentation.
- Exact idle looping rules with blinking and whether loopable motion must be periodic by construction.
- Default output pixel scaling, future preset migration rules, and schema-version changes beyond the approved project JSON v4.


Do not silently resolve any of these as if already user-approved.
