# Issue #66 — 透過PNG待機クリップのOTIO/Resolve互換性PoC

これは**製品機能ではなく検証用生成器**です。待機静止画の本実装、複数キャラの統合OTIO、待機UI、丸め規則は2026-11-23に四捨五入（同点切り上げ、正の待機は最低1フレーム）と決定しました。製品への統合は後続Issueです。

## 参考となるResolve生成OTIO（2026-11-23提供）

添付されたResolve生成OTIOでは、30fpsの5秒待機が次の形で書かれていました。

- 映像トラックの Clip.2 が ExternalReference.1 で透過PNGを通常の絶対ファイルパスとして参照
- 参照素材の available_range.duration は **1/30秒**（1フレーム）
- クリップの source_range.duration は **150/30秒**（5秒）
- 同じ長さの Audio トラック上の Gap.1
- Resolve固有の各種 effects メタデータあり。ただし**必要性は未検証**
- 元の global_start_time は30fpsの108000フレーム（1時間）。PoCでは0を用いる

参考OTIOに含まれる個人の素材パス・PNG本体はリポジトリに追加しません。

## 検証生成器

~~~sh
cd "$HOME/Code/tachie-motion"
source .venv/bin/activate
python -m tachie_motion.timeline.still_probe \
  --output-dir "$HOME/Desktop/tachie-issue66-probe"
~~~

指定フォルダに320×240の非対称・半透過領域付き**合成RGBA PNG**を1枚と、以下の13個のOTIOを生成します。既存ファイルは一切上書きしません。すでにフォルダに出力がある場合は別の出力フォルダを使用してください。

自分の透過PNGを試すときは --image "/path/to/file.png" を加えます。元画像は読み取りのみです。入力画像はRGBA・一部透過ありに限定します。

| FPS | ちょうど2秒 | 1.02秒 floor | 1.02秒 ceil |
| --- | ---: | ---: | ---: |
| 24 | 48f | 24f = 1秒 | 25f ≒ 1.041667秒 |
| 30 | 60f | 30f = 1秒 | 31f ≒ 1.033333秒 |
| 60 | 120f | 61f ≒ 1.016667秒 | 62f ≒ 1.033333秒 |

加えて各FPSの still_*fps_1p02s_nearest.otio は採用規則で丸めた結果（24fps=24f、30fps=31f、60fps=61f）です。また still_30fps_repeat.otio で同じPNGを30f + 60fの2クリップとして連続参照します。各OTIOは映像クリップと等尺の音声Gapを持ちますが、音声メディアは参照しません。

floorとceilは**互換性比較のため**引き続き併記しています。採用したのはnearest（四捨五入、0.5フレーム以上は切り上げ）です。`frames = max(1, floor(seconds × fps + 1/2))` （seconds > 0）。実装では Fraction と整数演算を使用し、floatは入力として認めません。秒数が文字列の場合は `Fraction(str_value)` 等で正確に変換してから渡します。実際の総待機時間は各区間を整数フレームに変換した値の総和です。24/30/60fpsのfloor/ceilはHuman PASSですが、nearestファイルは旧floorまたはceilと同じ長さになるため、採用計算そのものは新CIテストで検証します。

## Mac DaVinci Resolve Human E2E — 部分PASS（2026-11-23）

利用者報告によるPASS範囲：
- 30fps・2秒のPNG OTIO読込、画像表示・透明表示、60フレーム尺
- 30fpsの同一PNGを2クリップで反復参照
- Resolve上で静止画クリップの右端を延長
- 24fps／60fpsの2秒尺
- 24/30/60fpsそれぞれの1.02秒 floor／ceil 両候補のDuration表示

**まだ確認していないこと：** PNGの異名／別ディレクトリを指定したOTIOの自動リンク、実PSDプリセット由来の固定透過キャンバスの画質一致、独立コード監査。通常の合成PNG表示に関するHuman PASSをこれらへ拡張しない。

### 再現・追加確認手順

1. DaVinci Resolveで新しい検証用プロジェクトを用意し、24/30/60fpsのテストでは**各タイムラインfpsを対応値に設定**します。既存作品のタイムラインを変更しないでください。
2. 生成した各OTIOをタイムラインとして読み込みます。メディアが自動的にオンラインとなるか、PNGのパスが変化しないかを確認します。
3. 背景色をPNGの下に配置して、完全透明領域・不透明領域・半透明の青矩形・輪郭のアルファを確認します。黒背景への焼き込み、ハロー、位置ずれ、左右上下のクロップを記録します。
4. exact/floor/ceilのクリップ長をResolveのフレーム単位で確認します。クリップ右端を延ばし、同じPNGを引き続き保持できるかを確認します。
5. repeatでは2クリップがともにオンライン・同じ画像であり、長さが30fと60fであること、不要な映像や音声が追加されないことを確認します。
6. 日本語・空白・結合文字を含むPNGのパスで自動リンクを確認します。可能なら別名／別ディレクトリにコピーしたPNGを別の新規出力フォルダから参照するケースも確認します。
7. トラブル時は対象OTIO名、Resolveバージョン、タイムラインfps、表示症状、実際のフレーム数を残します。問題があった場合は不具合の再現条件と取り込みログを添えてIssue #66へ記録します。

**結果の区別：** Python構造テスト／公式OTIOラウンドトリップは機械的な構文・時間検証であり、Resolveの表示・透明度・読み込み成功を意味しません。実PSD原本を使った画質一致、固定透過キャンバス、製品への組み込みは別ゲートです。
