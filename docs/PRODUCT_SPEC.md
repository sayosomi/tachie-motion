# Product specification — agreed scope

Status: agreed product requirements updated 2026-10-31 (JST). This is a product contract, not evidence that code exists.

## 1. 用途・利用環境

- macOS/Windowsで使うローカルWebアプリ。Linuxは将来を見越してOS依存部分を分離する。
- インターネット常時接続は不要。利用者がFFmpegをインストールする。
- 専用画面で立ち絵アニメーションを作り、動画編集ソフトではMOVの位置・拡大縮小を手動設定する。
- DaVinci Resolveだけでなく他の編集ソフトでも素材を再利用できる設計。
- 初期版では動画全体の編集、字幕、BGM、背景、画面上の複数キャラ配置は行わない。

## 2. PSDとキャラクター

- 1キャラクターにつき元のPSDファイルは1つ。PSD自体は変更・再構成しない。
- 元のレイヤー階層、順序、名前、表示状態をそのまま読み込んで操作できる。
- 目・口のアニメーション対象はユーザーが手動指定。命名規則や自動分類は不要。1つの口形・目の状態は複数のPSDレイヤーから構成できる（白目＋黒目など）。
- **表情とポーズは分離せず、名前付きの1つのプリセットに統合する。** 例えば「通常」「にっこり」「しょんぼり」「びっくり」。プリセットは元PSDの階層・順序を維持した各レイヤーの表示ON／OFF（2状態）を保持する。ユーザーに各レイヤーの3状態指定を要求しない。
- キャラクター設定のトップページにはプリセット一覧・プレビューを表示し、各プリセットの詳細はページ遷移して編集する。新規作成、独立した複製、自由な名前変更、確認付き削除、ドラッグ＆ドロップによる並べ替えに対応する。
- プリセットの内部IDは名前・表示順とは独立して安定とし、名前変更・並び替えによってタイムラインや保存済みプロジェクトの参照が壊れないようにする。キャラクターごとに既定のプリセットを設定できる。
- 1つのプリセットは、**任意のopen口形セット（閉口・開口）と、任意のaiueo口形セット（あ・い・う・え・お・ん）を両方保存できる。** 各セットは独立して登録可能で、プリセットを「にっこり（open）」「にっこり（aiueo）」に複製する必要はない。口形の定義は複数レイヤーのON／OFFの組合せに対応する。
- プリセットごとに瞬きをする／しないを持ち、する場合は複数レイヤー対応の「開いた目」「閉じた目」の表示状態を登録する。
- プリセットの表示状態を基本とし、口パク・瞬きの動作中は**登録されたアニメーション対象のレイヤー群だけ**を切り替える。他のレイヤーは変更しない。親グループの可視状態・口と目で対象が重複する場合などの優先順位は設計上の未決事項とする。
- キャラクター設定はプロジェクト間で再利用。制作プロジェクトは使用設定のスナップショットを保持して過去の出力が無断で変わらないようにする。

## 3. WAV・口パク

- 複数のWAVを一括登録、並べ替え、一覧から削除できる（元ファイルは削除しない）。
- WAVごとにキャラクターとプリセットを割り当て、**WAV×キャラクター項目ごと**に口パク方式「なし」「open（音量連動）」「aiueo（LAB母音）」を選択する。使用するプリセット側に対応口形セットが登録されていること。
- **open**はプリセット内の閉口・開口をWAVの音量に連動させる。**aiueo**はLABの音素・時刻に対応してあ・い・う・え・お・んを切り替え、「ん」を無音時の口にも使用する。
- WAVの選択時、同じディレクトリ・同じベース名で拡張子だけを `.wav` → `.lab` と置き換えた隣接ファイルを自動確認する。日本語・空白・Unicode結合文字を含む元の名前を勝手に正規化・改名しない。存在に加えLABの形式・時間範囲・音素を検証し、検出成功／不在／不正の結果を区別して表示する。
- **有効な対応LABがないWAVではaiueo口パクは利用不可。** 音量から母音を推定したり、無断でopen等へフォールバックしない。LABなしでもopen・なしは利用できる。別名／別場所のLABを明示的に指定する導線は将来の補助機能とする。
- 「なし」でもWAVの再生、波形表示、シーク、プリセット変更、瞬きが可能。
- 1 WAVから複数キャラクターのMOVを生成できる。話者と聞き手のリアクションを別々に編集する。
- セリフアニメーションはWAVを時間基準にする。動画側の尺はフレーム単位で丸め、同期を保持する。

## 4. タイムライン操作

- WAV項目・待機項目ごと、キャラクターごとに独立した初期プリセットとプリセット変更点を持つ。前の項目から状態を継承しない。
- 編集方式は「変更点追加」。現在時刻にプリセット変更点を作り、次の変更点まで状態を維持する。
- 変更点は移動・削除・プリセットの差し替えができる。
- WAVの再生・波形・シークで変更点を編集できる。
- 口パクと瞬きは通常は自動処理。プリセット変更点とは別に計算する。

## 5. 瞬きと待機モーション

- 瞬き間隔はキャラクターごとに指定。ランダム揺らぎ・開始位相の違いで複数キャラクターが同時に瞬きするのを避ける。
- 同設定の再書き出しではタイミングを再現可能（乱数シード固定）。
- プリセットごとに瞬きON/OFFを指定。ニコニコ目や閉じ目などはOFF可能。瞬きON時の開眼・閉眼状態は複数レイヤーの組合せを登録できる。
- WAVなしで任意尺の待機を作成できる。口パクなし、瞬き、表情・ポーズ変更点を利用。
- 汎用の待機モーションはループ可能なMOVとしてライブラリ化し、同じファイルを複数位置で再利用する。
- 場面専用待機は独立した編集・書き出し単位。ループの継ぎ目の自然さは検証対象。

## 6. 映像とOTIO出力

- 基本映像形式は透過MOV（ProRes 4444）。初期はPNG連番・WebM・FCPXML・EDLは対象外。
- 出力解像度は「立ち絵の必要領域のみ」。PSDの不要な透明余白は含めない。
- キャラクターで使用する全ポーズ・表情・口・目・揺れが収まる範囲を計算し、キャンバスと基準位置を固定。途中の表情変更や個別再生成で位置がずれない。
- 基本30fps、選択肢として24/60fps。変更時の影響は明示する。
- WAVごとのキャラクター別MOV、必要な待機MOVを出力。
- OTIOは「全体（timeline.otio）」と「各セリフ/待機の個別OTIO」の両方を出力。
- 全体OTIOは項目順。WAVを音声トラックに1回だけ配置し、キャラクターごとに別映像トラックを用いる。
- 個別OTIOは対応するMOVとWAV（待機はMOVのみ）を同期したタイムライン。
- MOV/WAVはOTIO間で重複生成しない。同じ既存MOVを複数箇所から参照できる。
- 持ち運び可能な出力セットでは元WAVを変更せずmedia/へコピーし、OTIOはそこを参照する。
- 編集済みMOVだけ再生成できる。セリフ順だけの変更はOTIOのみ再生成。
- すべての編集ソフトのOTIO相互運用性は保証せず、対応実機で検証して互換性範囲を明記する。

## 7. 保存・診断

- キャラクター設定（PSD参照・統合プリセットのON/OFFと口形／目状態・安定ID）と制作プロジェクトを分けて保存（構造化JSON等）。
- プロジェクトは参照元PSD/WAV、スナップショット、編集点、出力設定、乱数シードを管理。
- 参照切れは警告して再指定。無断で元素材を上書きしない。
- 生成エンジンはCLIからも起動でき、GUI・テストで同じ結果を出せる。
- 診断に操作・生成・FFmpegのログを記録し、素材本体の自動収集はしない。
